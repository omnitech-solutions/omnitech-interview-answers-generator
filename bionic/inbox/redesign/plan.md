### 7.17 Capture the display of the last-focused browser, and show which display (user request)

- Cause found: a whole-screen or region capture (`ShellCapture.capture`, `.display`/`.region`) uses `CGMainDisplayID()`, the display with the menu bar, so it ignores where the last-focused Chrome window is. Focused-window mode already follows the last non-shell app (`FocusSampling`) but picks that app's LARGEST on-screen window (`FocusedWindow.choose`), not its most recently focused one. Nothing tells the user which display a screenshot came from (only `windowLabel`, an app name).
- Design (D32): (1) resolve the capture display from the sampled browser's frontmost qualifying window (CGWindowList is front-to-back; display = the one holding the window's centre), falling back to the display sampled at receipt; (2) focused-window picks the frontmost qualifying window of the sampled app, not the largest; (3) the capture result and the stored screenshot carry a closed display label (`displayName` from `NSScreen.localizedName`, plus "n of m" when more than one display), added to `studio-host.ts` with Swift parity and the capability test; (4) the indicator shows on the Auto/Manual capture strip, each screenshot thumbnail and the zoom viewer, and in the transcript row ("Screen: Chrome, Display 2 of 3"); (5) region masks keep their display binding, and a region defined on another display is still refused, never remapped.
- Safety: only a browser in front is ever looked at (`BrowserFocus.allows`); the shell's own windows stay excluded; no widening to another app; the label is a display name, never window titles or URLs (rule 8).

## 8. Where a task's screenshots live

A task has revisions (`task_id`, `task_revision`); each revision's action stores the observation ids it was built on in `interview.session_actions.source_event_ids` (a `text[]`). The screenshot ones are `snap/{session_id}/{source_id}/{event_id}`; spoken segments (`heard/...`) and owner inputs (`input/...`) share the array and are ignored here. The images are `interview.session_observations` rows with `kind = 'screen.snapshot'`, keyed `(tenant_id, owner_user_id, session_id, source_id, event_id)`, whose `screenshot_artifact_id` points at `platform.artifacts` (`NULL` when no image was stored). Bytes sit in `platform.artifact_payloads`.

The shown ordinal `S{n}` is the rank of the screenshot among ALL of the session's `screen.snapshot` observations by `sequence` (the browser's `snapshotOrdinals`), so rank before narrowing to the task. One query for psql (set `\set sid '...'` and `\set task '...'`):

```sql
SELECT o.ordinal, o.source_id, o.event_id, o.sequence, o.received_at,
       o.screenshot_artifact_id,
       array_agg(DISTINCT a.task_revision ORDER BY a.task_revision) AS revisions
FROM (SELECT *, row_number() OVER (ORDER BY sequence) AS ordinal
      FROM interview.session_observations
      WHERE session_id = :'sid' AND kind = 'screen.snapshot') o
JOIN interview.session_actions a
  ON a.tenant_id = o.tenant_id AND a.owner_user_id = o.owner_user_id
 AND a.session_id = o.session_id AND a.task_id = :'task'
 AND 'snap/' || a.session_id || '/' || o.source_id || '/' || o.event_id
     = ANY (a.source_event_ids)
GROUP BY o.ordinal, o.source_id, o.event_id, o.sequence, o.received_at,
         o.screenshot_artifact_id
ORDER BY o.sequence;
```

A task with no rows built on speech alone (or its screenshot was never linked). Over HTTP the same list is `GET /api/interview/t/:tenantSlug/sessions/:id/tasks/:taskId/screenshots` (owner-only, ids/ordinals/times only); fetch an image with the existing `GET .../sessions/:id/screenshots/:artifactId`.
