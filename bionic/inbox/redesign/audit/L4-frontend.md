# L4 audit: frontend (React, Next shell, product UIs)

## 1. Scope and method

Inspected (read-only, working tree at audit time): `products/interview/src/frontend/**` (studio/*; live/* only at seams: storage keys, timers, boundaries), `products/presentation/src/frontend/**`, `apps/web/app/**` and `apps/web/src/platform/*` (pages, layouts, route handlers, shell, registry), `packages/interview-api-client`, vendored `@oc-tech/omni-ui-components` usage, shared CSS/tokens. Next is `^16.2.3` (apps/web/package.json); App Router.

Commands run: `git grep -n -E "from ['\"](@omnitech/web|[./]*apps/web)" -- 'products/*/src/**'` (INV-0007: **pass, no output**); `git grep ... "from ['\"]next(/|['\"])" -- 'products/*/src/**'` (INV-0008 variant over the whole product, not only backend: **no output**); scripted greps for listeners/timers/storage/dialogs/dangerouslySetInnerHTML/a11y; Knip production results from `baseline/runs/t07b-after/knip-production.json` filtered to this slice. Not inspected: Studio Live overlay behaviour (just redesigned), Swift shells, backend code beyond the seams, rendered pixels/contrast (no browser run), bundle analysis (no build; bundle remarks are from import graph reading). Next.js docs were not re-fetched this session; server/client boundary statements rely on https://nextjs.org/docs/app/getting-started/server-and-client-components and are marked inferred where version-specific.

## 6. What is already good

- INV-0007 and INV-0008 hold; product frontends import only contracts, `interview-api-client`, assistant SDK/react, own domain (presentation `domain/*` is pure, no I/O). `interview-api-client` depends only on `interview-contracts`.
- Build-time registration is clean: `registry.ts` registers manifests; `frontendPlugin` routes are dynamic imports; membership resolves before the product page loads (`ProductPage:39-43`, `[SAFETY]` comment), with `Object.hasOwn` guard on frames.
- Heavy libs are deferred: Mermaid, Panzoom, Shiki core and language grammars are dynamic imports; studio and overlay are separate lazy chunks; no barrel-import problem found in this slice.
- Markdown rendering is safe: `react-markdown` without raw HTML, Mermaid `securityLevel: "strict"`, only three `dangerouslySetInnerHTML` sites (SVG from Mermaid, Shiki HTML).
- Effect hygiene is generally strong: `useStudioLists` aborts superseded requests and ignores stale results; `platform-shell` aborts its load and removes its listener; `useStoredFlag`, `playground-control`, `matrix-picker` guard storage; `useToast` clears its timer; `role="status"` toast; `aria-label`s on presentation inputs.
- Server/client boundary: shell pages are server components; only `PlatformShell` and product entries are `"use client"`; sign-in uses server actions; public share page bypasses tenant routes deliberately (backend must enforce the token).
- Vendored omni-ui library is consumed only as `styles.css` in `layout.tsx` (no component duplication to reconcile; interview and presentation define their own token sets in `tokens.css`/`presentation.css`, a duplication risk only if a shared token layer is later wanted).
