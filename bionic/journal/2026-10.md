## [2026-10-03 02:52] implementation | ADR-0010 parallel document generation delivery

I expected the one-call document path to be simpler, but the largest built-in template spent minutes waiting for a single response; splitting every section also multiplied prompt and prose cost.
The accepted decision kept contiguous fields together in a few bounded parallel calls. The worker then needed concurrency and lease handling so those calls could actually run at once without a second worker taking a live job.
I would benchmark the largest template and inspect worker ownership before choosing call boundaries again; the missing terminal events and loop isolation were recorded as follow-ons instead of being hidden in the delivery claim.
Friction: one-call latency and per-section cost pulled in opposite directions, so call count alone was not a useful target.
